수집되는 기록:
- 내장 AI, 코딩 에이전트, **실무자 에이전트(업무 담당자)**와의 대화

- [ ] 키보드: 노트북 내장 키보드 + **유선 키보드 1개까지**. 블루투스 키보드·마우스 불가

- [ ] 권장 사양: iPhone 11 이상 / iOS 16 이상, 또는 Android 11 이상 / RAM 4GB 이상
- [ ] 여유 저장 공간 1GB 이상
- [ ] iOS는 앱을 최신 버전으로 업데이트, Android는 안내된 경로에서 APK를 다시 받아 설치
- [ ] **충전선 연결 필수**, 거치대, **Wi-Fi 연결**, 방해금지 모드

## 4. 감독 절차

1. 링크 접속 → "계속" → 응시 규정을 끝까지 스크롤하고 동의
2. 감독 안내 동의 → 웹캠 → **전체 화면** 공유 (창이나 탭 공유는 안 됨) → 휴대폰 연결
   - Proctor는 **설치 QR과 연결 QR이 다릅니다**. 연결 QR은 Proctor 앱 안에서 스캔합니다.
3. **'과제 시작'을 누르면 녹화가 자동으로 시작**됩니다. 그 뒤에:
   - 휴대폰 거치: 앉은 자세에서 한쪽 팔을 옆으로 뻗어 손끝이 닿는 책상 위에 **세로로** 놓습니다. **손·키보드, 얼굴, 모니터**가 함께 보이게 합니다.
   - 신분증을 얼굴 옆에 나란히 들고 Proctor 카메라(웹캠이 아님)에 보여줍니다.
   - 안경을 쓰면 안경 앞면과 양쪽 안경다리의 바깥쪽·안쪽을 보여준 뒤 다시 씁니다 (스마트 안경 확인).
4. 응시 중에는 **전체화면을 유지**해야 하고, 화면 이탈과 **캡처 단축키를 감지**합니다 (Mac `⌘⇧3/4/5` 누르지 않기).
5. 음식과 음료는 먹을 수 있습니다. 카메라와 화면을 가리지 않고, 타이머는 계속 흐릅니다.

## 5. 작업 환경 (웹 IDE)

- 구성: 상단 바 (남은 시간, 감독 상태, CPU/RAM, **문제 신고**, **제출하고 문제풀기**) / 파일 탐색기 / 에디터 / 터미널 / 메신저
- 메신저 상대:
  - **Cofa Helper**: 화면 사용법, 제출 절차
  - **업무 담당자 (실무자 에이전트)**: 과제의 업무 맥락
- **Codex**: 터미널에서 `codex` → `/status`로 모델과 권한 확인 → `/model`로 모델 선택. 기본은 필요할 때 승인을 요청하는 모드입니다.
- **서버는 `0.0.0.0`에 바인딩**합니다 (localhost만 쓰면 미리보기가 안 될 수 있음). 왼쪽 Browser 도구에서 PORT와 경로를 입력하고 새로고침을 누릅니다.
- 서버를 실행 중인 터미널 탭은 닫지 않습니다. 새 터미널은 `+`, 붙여넣기는 `Ctrl+Shift+V` (Mac `⌘V`)
- **MCP 탭**에서 MCP 서버 설정 JSON을 편집할 수 있습니다 (필요할 때만).
- 내 PC의 파일은 **업로드할 수 없습니다**. 에디터는 자동 저장되고, `Ctrl+S`로 바로 저장할 수도 있습니다.
- AI나 터미널이 같은 파일을 수정하면 저장 충돌이 납니다 → "외부 변경 불러오기" 또는 "현재 내용으로 저장" 중 선택
- 입력이 없으면 "일시정지" 안내가 뜰 수 있지만 **타이머는 멈추지 않습니다**.
- 내 프로세스를 과하게 써서 생긴 OOM(메모리 부족)은 구제되지 않습니다.

| ⭕ 허용 | ❌ 금지 |
|---|---|
| 응시 환경의 **Codex** | **Claude Code**, 다른 AI 모델 연결, **Astra**, 개인 API 키, 개인 유료 구독 |
| 공개 **Skill, MCP, Plugin** | 비공개 Skill 또는 개인 PC 파일 업로드 |
| 공개 GitHub 저장소 **Git Clone**, 다운로드 | **Git Push**, 문제·파일·결과물의 외부 전송이나 공유 (모니터링하며 법적 조치 대상) |
| 외부 소스코드 참고, 일부 알고리즘 차용 | 외부 자료로 결과물을 **통째로 대체** |
| 필요한 정보를 **플랫폼 안에서 AI로** 찾기 | 외부 브라우저로 직접 접속, 다른 기기의 AI 사용 |
| 작업 환경 안에서 복사·붙여넣기 (과제 허용 범위 안) | 문제나 답안의 캡처·외부 복사·게시 |
| | 감독·보안 기능을 끄거나 설정·경로를 바꿔 우회하기, **Computer Use** (모든 단계) |
| | 대리 응시, 타인의 도움, 응시자끼리 답안 교환 |

- 활용하는 공개 저장소는 **2차 예선 결과가 나올 때까지 공개 상태를 유지**해야 합니다.
- 플랫폼 관리 설정이나 연결 프로세스를 수정·종료하지 말고, 키와 토큰을 공개하지 않습니다.

### 즉시 탈락 사유 (직접 확인된 경우)
대리 수행 / 타인에게 답안이나 코드를 받아 반영 / 응시자 간 답안 교환이나 공동 풀이 / 허용되지 않은 도구로 만든 답안을 반입

### 추가 확인 대상 (정황만으로 탈락시키지는 않음)
신원 정보 불일치, 스마트 안경, 휴대폰 반복 조작, 이어폰이나 대화, 다른 웹·메신저·AI 창, 원격 조작 의심, 카메라 가림. 불가피한 상황이 생기면 **시각과 사유를 기록**해 둡니다.

## 7. 제출과 후속 서술형

### 제출
1. **종료 10분 전에 제출을 시작**하는 것을 권장합니다. 필수 파일의 경로와 저장 상태를 먼저 확인합니다.
2. "제출하고 문제풀기" → 미리보기 (일부 파일만 보이는 것은 정상) → **"제출물 확정하고 문제풀기"** (확정 후 수정 불가)

### 후속 서술형
- **AI 사용 금지, 복사·붙여넣기 불가**, 직접 입력
- **제출물과 작업 기록을 바탕으로** 문항이 생성됩니다.
- 문항당 5분이며, 다음 문항은 직전 답안을 제출한 순간부터 시간이 갑니다. 이전 문항으로 돌아갈 수 없고, 시간이 끝나면 자동 확정됩니다.
- 질문의 전제가 실제 구현과 다르면 **차이를 밝히고** 내 작업을 설명합니다.
- 마지막에 "답안 제출하고 마치기"를 누른 뒤 **"과제가 잘 제출됐어요"와 제출 ID·시각·파일 수·크기**를 확인합니다.
- 서술형 화면에는 신고 버튼이 없습니다. 오류가 나면 문항 번호와 시각을 기록해 둡니다.

## 8. 문제 대응

| 상황 | 대응 |
|---|---|
| 사용법이나 제출 절차 | Cofa Helper |
| 접속 장애, 반복 오류, 감독 연결 | 상단 **"문제 신고"** → 유형 선택, 발생 시각, 단계, 직전 동작, 오류 문구 (키나 토큰은 적지 않기) |
| 감독 장치가 끊김 | "감독 연결" → "연결 확인" → 끊긴 장치만 다시 연결 |
| 탭을 닫거나 새로고침함 | 같은 링크로 재입장 → 카메라, 화면 공유, Proctor 다시 연결 (작업은 서버에 저장된 기준으로 이어짐) |
| 한 영역만 멈춤 | "이 영역 다시 불러오기" |
| 터미널 오류 | "다시 연결" 또는 `+`로 새 터미널 |
| 긴급문자나 알림 | 휴대폰을 거치한 채로 Proctor 상태 확인 |

신고를 해도 타이머는 멈추거나 연장되지 않습니다. 모델·API 등 플랫폼 내부 장애로 재응시할지는 나중에 공지됩니다.
