# 과제 이해 (Intake)

목표: 코드를 쓰기 전에 **무엇을, 누구를 위해, 어떤 기준으로** 만드는지 확정한다. 이 단계에서는 코드를 작성하지 않는다.

## 절차
1. 구조 파악 (짧게)
   - `ls -la`, `find . -maxdepth 2 -type f -not -path './.git/*' | head -50`, `git log --oneline | head -5`
2. README와 과제 안내 문서는 전부 읽는다. 다른 파일은 필요한 부분만 읽는다.
3. 데이터 파일은 크기부터 확인(`wc -l`, `du -h`)하고, 앞부분(`head -5`)과 스키마만 본다. 전체를 출력하지 않는다.
   - CSV: 컬럼, 행 수, 결측, 고유값이 적은 컬럼 / JSON: 최상위 키와 샘플 1개
4. 기존 코드가 있으면 진입점, 실행 방법, 테스트 위치만 파악한다.

## 출력 형식
1. **과제 목표**: 한 문장 (누가 / 무엇을 / 왜)
2. **요구사항 표**

   | # | 요구사항 | 구분 | 출처 (README 원문 짧게 인용) |
   |---|---|---|---|
   | R1 | | 필수 / 선택 / 모호 | |

3. **제출물 체크리스트**: 파일명, 형식, 위치. README 문구 그대로 적는다.
4. **명시된 평가 기준**: README에 적힌 것만 쓴다. 추정한 것은 "(추정)"으로 표시한다.
5. **숨은 제약**: 지정된 스택, 포트, 데이터 사용 범위, 금지 사항
6. **업무 담당자 질문** (최대 5개, 중요한 순서)
   - 형식: `질문` → 이 답에 따라 바뀌는 결정
   - 예/아니오나 선택지로 답할 수 있게 쓴다.
     - 좋은 예: "대시보드는 실시간 갱신이 필요한가요, 하루 한 번 집계면 충분한가요?"
     - 나쁜 예: "어떤 기능이 필요하세요?"
7. **답이 오기 전 가정**: 질문마다 기본 가정 한 줄 (이 가정으로 진행해도 되는지 나에게 확인받는다)
